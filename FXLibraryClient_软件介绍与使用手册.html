1软件介绍

FX Library 是一个独立的桌面客户端（Python + PySide6 / Qt），用于集中管理 Unreal Engine 5 中的 Niagara 系统与 Cascade 粒子系统。它把散布在多个项目的特效资产统一编目、生成缩略图、打标签、收藏，并支持以自包含的 .fxpack 包在任意项目间一键搬运——且默认完全不依赖 UE 编辑器即可工作。

🗂️

统一资产库

扫描本地任意目录中的 .uasset，用纯 Python 字节识别 Niagara / Cascade，自动编入本地 SQLite 索引。

🖼️

离线缩略图

直接从 .uasset 内嵌数据读取引擎缩略图（无需启动 UE），没有时生成风格化占位图。

📦

自包含迁移

导出 .fxpack（标准 .uasset + 依赖 + 清单 + 缩略图），导入零配置、不变粉。

🔖

标签·收藏·评分

为每个特效添加标签、收藏星标、五星评分与备注，右侧 Inspector 一目了然。

极速检索

顶部搜索框按名称 / 标签 / 路径实时过滤，下拉筛选按类型、来源、排序组合。

整体架构

FX Library 采用「纯客户端 + 可选 UE 无头桥」架构。日常使用（编目、缩略图、标签、检索、导出/导入 .fxpack）全部纯 Python 完成，不需要安装或运行 UE。只有在你想用 UE 渲染「真实播放帧缩略图」时才需要配置 UnrealEditor.exe。

2安装与配置

FX Library 以独立可执行程序（.exe）形式分发，无需安装、解压即用。

系统要求

项目要求
操作系统Windows 10 / 11（64 位）
运行时程序自带 Python 运行环境，无需单独安装 Python
UE 编辑器可选。仅在需要「真实渲染缩略图」时，本机需装有 UE 5.x 并配置 UnrealEditor.exe 路径
磁盘程序约 3 MB；缩略图缓存与复制存档随库规模增长（位于 ~/.fxlibrary/）

首次启动与设置

  1. 双击 FXLibraryClient.exe 启动程序，进入默认暗色主题主界面。
  2. 点击右上角 ⚙ 设置 按钮，打开设置对话框。
  3. 语言：可选「中文 / English / 跟随系统」。当前界面语言即时生效。
  4. 主题：当前版本聚焦暗色主题（Stripe 柔光风格），提供最舒适的浏览体验。
  5. 仅导入 FX 特效：勾选后扫描会自动跳过非 Niagara/Cascade 的 .uasset（如纯蓝图、材质、网格），保持库内只存单特效。
  6. 添加文件夹时不再询问导入方式：勾选后，每次添加文件夹直接使用已保存的导入模式，省去弹窗。
  7. Unreal Editor 路径：点击「浏览」选择本机的 UnrealEditor.exe（如 C:/UE_5.4/Engine/Binaries/Win64/UnrealEditor.exe）。留空也能用——只是无法渲染真实播放帧缩略图。
  8. 点击「确定」保存配置。配置写入 %USERPROFILE%/.fxlibrary/config.json。
图 2-1 · 设置对话框（示意）

两种导入模式

添加文件夹扫描时，程序会询问以何种方式纳入资产（可在设置中关闭此询问，直接使用上次选择）：

模式行为适用场景
引用 Reference保留 .uasset 在原位置，库只记录路径与缩略图索引。不复制文件。特效仍在原项目内、只想编目浏览（默认推荐）
复制 Copy把 .uasset 复制进库的 files/ 目录，成为库自己的副本。想把特效收拢进统一库、脱离原项目独立管理
数据安全提示：「引用」模式下，删除/永久删除操作只影响库索引，绝不触碰你的原始文件；「复制」模式下永久删除也只清理库内副本（files/ 与 thumbs/），并设有路径安全围栏，绝不会删到库目录之外。

4核心功能详解

4.1 扫描目录，建立资产库

点击工具栏 ＋ 扫描目录，选择一个包含 .uasset 的文件夹（通常是某个 UE 项目的 Content/ 目录，或任意磁盘目录）。扫描过程完全在后台线程进行，不会卡住界面。

图 4-1 · 扫描数据流
  • 纯 Python 类型识别：通过扫描 .uasset 包名表字节，判断是 Niagara 系统（NiagaraSystem）、Cascade 粒子（ParticleSystem）还是未知类型；若文件是内嵌了特效的蓝图，会标记为 BP 徽章并正常收录，不会漏掉。
  • 缩略图：优先读取资产内嵌的引擎缩略图；读不到则生成风格化占位图（见 4.2）。
  • 引用 vs 复制：按设置中的导入模式决定是只记录路径，还是把文件复制进库的 files/。
  • 拖拽导入：可直接把文件夹或 .uasset 文件拖入主窗口，自动开始扫描导入。

4.2 缩略图：三档策略

FX Library 让每个特效都有「一张图」可看，按来源分为三档（Tier）：

Tier来源是否需要 UE说明
Tier 1 · 引擎读取 .uasset 内嵌缩略图❌ 不需要纯 Python 解析包内缩略图数据，离线即用，是默认与最常用的一档。
Tier 3 · 手动用户指定图片❌ 不需要在 Inspector 点「指定缩略图」，选本地图片裁切成正方形；优先级最高，覆盖其他档。
Tier 4 · 占位程序生成❌ 不需要没有内嵌缩略图时，按类型生成渐变 + 类型字母（N/C/？）的风格化占位图，保证库内视觉一致。
关于「真实播放帧」：若你在设置中配置了 UnrealEditor.exe，可触发 UE 无头渲染来生成更接近真实播放效果的缩略图。这属于可选增强——绝大多数浏览、检索、迁移场景仅靠 Tier 1 内嵌图与 Tier 4 占位图即可完成，无需启动 UE。
  • 一键刷新全部缩略图：工具栏「🖼 读取缩略图」会对库内所有资产重新读取内嵌图（Tier 1），没有的回退为占位图。
  • 单资产重读：右键卡片 →「读取内嵌缩略图」，可只针对选中项刷新。
  • 手动指定：右键卡片 →「手动设置缩略图 (Tier 3)」，或 Inspector 内「指定缩略图」。

4.3 三种视图

图 4-2 · 图标 / 列表 / 详细信息 三种视图对比

4.4 搜索与筛选

  • 搜索框（顶部）：输入即过滤，匹配资产名称 / 标签 / 路径，250 毫秒防抖，边输入边出结果。
  • 类型：全部类型 / Niagara 系统 / Cascade 粒子。
  • 来源：全部来源 / 纯特效 / 含特效的蓝图（BP）。
  • 排序：名称 / 类型 / 导入日期 / 文件大小 / 评分 / 随机。
  • 左侧快捷筛选：未分类、未标签、有缩略图、无缩略图、收藏，一键过滤。
  • 视图分段（主区标题旁）：全部特效 / 收藏 / 最近。

4.6 虚拟文件夹

左侧「文件夹」区域点击 ＋ 可新建自定义虚拟文件夹（如「火焰特效」「Boss 技能」），右键任意卡片 →「添加到文件夹」即可把资产归入多个文件夹。虚拟文件夹是库的逻辑分组，不影响磁盘文件结构，也支持重命名与删除。

4.7 导出到 UE 工程

选中资产后，工具栏或右键菜单选择「复制到 Content 文件夹」，选择目标 UE 工程的 Content/ 目录（选到工程根也会自动识别 Content/）。程序会把资产及其依赖复制到目标目录。

未配置 UE 时的提示：若未检测到 UnrealEditor.exe，导出仍会把文件复制到所选文件夹，但不会真正导入进活的 UE 工程。如需引擎内的导入联动，请在设置中配置 UE 路径。

4.8 导出 .fxpack（自包含包）

选中一个或多个资产，点击工具栏「📦 导出 .fxpack」或右键「导出 .fxpack」，选择保存位置。这会生成一个 .fxpack 文件——一个自包含的压缩包，里面是 100% 标准的 .uasset，外加清单与缩略图。可邮件发送、上传、或导入任意项目。

4.9 导入 .fxpack

点击工具栏「导入 .fxpack」或 Inspector 内「导入 .fxpack」，选择 .fxpack 文件，程序解包把资产收进本地库（含缩略图）。导入零配置、不变粉——因为包内已经带齐了全部依赖 .uasset。

4.10 资产体检

点击工具栏「🩺 体检」，程序扫描库内全部资产，检查两类问题并弹出报告：

  • 源文件缺失 索引指向的 .uasset 在磁盘上已不存在（标为「损坏 / bad」）。
  • 名称重复 多个资产显示名相同（标为「警告 / warn」），便于发现冗余副本。

4.11 回收站与数据安全

删除资产采用软删除机制，先进入回收站，给你反悔的机会：

  • 移到回收站：右键卡片 →「移到回收站」，或选中后浮动批量条「🗑 批量移到回收站」。资产从主列表消失，但记录保留在回收站。
  • 恢复：切到左侧「回收站」，选中后批量条出现「恢复」。
  • 永久删除：在回收站选中后「永久删除」，才会真正清理库内副本（仅 files/ 与 thumbs/ 内、且位于库目录下的文件，设有路径安全围栏）。
  • 清空回收站：一次性清理全部回收项，操作前会二次确认。
重要：「引用」模式下，即使永久删除也只动库索引与（复制模式下的）库内副本，绝不会删除你原始项目里的 .uasset。复制模式下的删除还被限制为只能删库目录之内，杜绝误删库外文件。

5.fxpack 格式详解

.fxpack 不是新的资产格式，而是一个「带清单的 zip 容器」，里面装的 100% 是标准 .uasset。引擎不认识 .fxpack 后缀——它只在「库管理 / 分享」层存在；导入进 UE 后，资产全部回归原生 .uasset，引擎零感知。

图 5-1 · .fxpack 内部结构
成员作用
manifest.json我们附加的元数据：名称、类型、引擎版本、性能档、标签、作者、许可、依赖列表——.uasset 装不下的信息都放这里。
assets/全是标准 .uasset：特效本体 + 递归提取的材质 / 贴图 / 曲线 / 网格等全部依赖。
thumbs/静态缩略图（唯一预览产物，无视频）。
deps_graph.json依赖关系图，用于导入时把内部引用从「原始项目路径」重映射到「当前项目实际路径」。
为什么用 .fxpack 而不是裸 Migrate？ 一个 Niagara 特效从来不是单个文件，它引用材质、贴图、曲线、网格……只拷一个 .uasset 必然变粉。.fxpack 把特效 + 全部依赖捆成一个文件，别人导入零配置、不变粉，还能带上标签与缩略图做离线浏览。

7常见问题（FAQ）

Q：必须安装 Unreal Engine 才能用吗？

不需要。扫描、缩略图（读取内嵌图）、标签、收藏、检索、导出 / 导入 .fxpack 全部纯 Python 完成。只有想用 UE 渲染「真实播放帧缩略图」时才需要本机装有 UE 并配置路径。

Q：为什么有些卡片显示的是渐变占位图而不是真实画面？

那是因为该 .uasset 没有可被读取的内嵌缩略图（Tier 1 缺失），程序自动生成了 Tier 4 占位图。你可以右键 →「手动设置缩略图」指定一张图，或配置 UE 后渲染真实帧。

Q：导入 .fxpack 后打开变粉怎么办？

正常情况下不会——.fxpack 已递归打包全部依赖，导入零配置。若变粉，通常是源包本身在导出时依赖未完整收集，请用「资产体检」核对，或回到导出端重新打包。

Q：删除资产会删掉我项目里的原文件吗？

不会。「引用」模式只改库索引；「复制」模式的永久删除也只清理库目录（files/、thumbs/）内的副本，且有路径安全围栏，绝不动库外文件。

Q：扫描时为什么会跳过一些 .uasset？

若开启「仅导入 FX 特效」，非 Niagara/Cascade 的文件（纯蓝图、材质、网格等）会被跳过。这是预期行为，目的是保持库内只存单特效。

Q：库数据存在哪里？

配置文件 %USERPROFILE%/.fxlibrary/config.json，库本体（SQLite 索引 + thumbs/ 缩略图 + files/ 副本）默认在 %USERPROFILE%/.fxlibrary/library/。重装程序不会自动删这些。

8技术规格与数据模型

技术栈

  • 语言 / GUI：Python 3 + PySide6 (Qt 6)
  • 本地索引：SQLite
  • 缩略图：纯 Python 解析 .uasset 内嵌数据 + Pillow 生成占位图
  • 可选增强：UE 5.x 无头桥（-ExecutePythonScript + -RenderOffScreen）
  • 分发：PyInstaller 打包为独立 .exe

资产数据模型（FXAsset）

  • source_path：原始 .uasset 绝对路径（主键）
  • type：Niagara / Cascade / Unknown
  • blueprint：是否内嵌于蓝图（BP）
  • tags / favorite / rating / note：标签、收藏、评分(0–5)、备注
  • thumb_path / tier / has_thumb：缩略图路径、档位、是否真实图
  • health：ok / warn / bad
  • source：scan（扫描入库）/ fxpack（导入）

配置文件字段

字段含义默认值
ue_editor_pathUnrealEditor.exe 绝对路径（可选）空
library_dir库根目录（DB + thumbs + files）~/.fxlibrary/library
scan_roots「自动扫描」搜索的根目录列表[]
import_modereference（引用）/ copy（复制）reference
import_fx_only仅导入 FX，跳过未知类型true
read_thumbs_on_import导入时读取内嵌缩略图true
languageauto / zh / enauto
