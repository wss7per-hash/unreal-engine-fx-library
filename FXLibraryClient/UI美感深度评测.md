# FXLibraryClient · UI 美感 / 设计感 / 布局 深度评测

> 评测视角：**UI 设计师**（视觉审美 / 设计语言 / 布局构图 / 信息密度 / 品牌感）。
> 对照标尺：用户偏好的 **Stripe 风（清爽柔光渐变 + 层次阴影 + 呼吸感）**，以及"反对平淡标准布局"的明确要求。

## 〇、一句话结论

**这软件是"工程上合格的平庸设计"**——token 纪律扎实、对比度达标、焦点环可访问，但**视觉上缺乏设计感**：它长着一张"任何 SaaS 工具都能套的默认三栏皮"，所谓的"柔光渐变"基本没落地，色彩单调、层次薄弱、布局里有大块空洞也有大块拥挤。对于一款**以视觉特效（VFX）为管理对象**的工具，界面本身却是最不"特效"的那块面板——这是最讽刺、也最该改的点。

## 一、布局问题（Layout）

### 🔴 L-1 · 工具栏过载，无视觉分组
- **现状**：`main_window.py:703-828`，工具栏是两行、min-height 84px。第一行塞了**扫描(主按钮) + 读取缩略图 + 导出fxpack + 体检 + 全选 + 反选 + 清除** 共 7 个按钮；第二行是 **类型 / 来源 / 排序 / 视图 / 图标大小 5 个下拉 + 日志图标**。约 13 个控件挤在 84px 里，彼此只有 `spacing(8)` 的等距空隙，**没有任何分组、分隔或视觉聚类**。
- **问题**：认知负荷高——用户分不清"动作"和"筛选"的边界；窄窗下控件互相挤压。Stripe / Eagle 这类标杆会用**细分隔符或集群**把"主操作 / 筛选 / 视图"三簇分开。
- **方向**：拆成三簇（左=主操作 Scan；中=筛选下拉组，可用细分隔线或收纳为 popover；右=视图/工具）；或把 5 个筛选下拉收进一个"筛选"抽屉。

### 🟠 L-2 · 侧栏上方 ~200px 死区（已知 P1-J，仍在校验）
- **现状**：侧栏垂直 splitter 把上区压到约 200px，但上半区只剩"未分类 / 未标签"两个短按钮 + `addStretch`，下面文件夹树被挤到 320px 区。
- **问题**：大面积纵向空白 + 下方信息挤作一团，空间利用失衡，视觉重心歪掉。
- **方向**：去掉垂直 splitter，把"快捷筛选 + 标签区 + 文件夹树"合并进**单一自然流滚动容器**；或在顶部空区放一张**品牌/统计 hero 卡**（如"本库 1,284 个资产 · 96 已收藏"），把死区变信息资产。

### 🟠 L-3 · 标准三栏 IDE 套路，缺乏设计个性
- **现状**：侧栏 / 内容区 / 检查器（右抽屉）是桌面工具最安全的默认结构，没有任何出挑的构图。
- **问题**：用户明确反感"平淡标准布局"。当前结构**功能正确但零惊喜**，对一款创意工具尤其可惜。
- **方向**：可在内容区顶部引入一条**柔和渐变 hero 带**（当前筛选/标题区），或在侧栏加品牌色块、在检查器加视觉锚点，打破"全是灰白卡片"的均质感。

### 🟡 L-4 · 内容头单薄，缺上下文
- **现状**：`_build_main_area:832-856`，内容头只有 `标题 + 计数 + 视图段控(全部/收藏/最近) + 选择提示`，左右大量留白，没有面包屑、没有视图专属操作位。
- **问题**：头区"撑不满"，既空又没用。
- **方向**：头区可承载当前筛选的面包屑 + 视图切换的 contextual 操作（如详情视图的"列设置"）。

### 🟡 L-5 · 密度失衡：工具栏挤、侧栏空
- 同一界面里，工具栏 84px 塞 13 控件（过密），侧栏上区 200px 全空（过疏）。**空间语言不统一**，显得没经过整体排版。

## 二、美感 / 设计语言问题（Aesthetics）

### 🔴 A-1 · "柔光渐变"名不副实（核心扣分点）
- **现状**：`style.py` 定义了 `accent2: #00a3ff`（青）意图做双色渐变，但**几乎从未使用**——`#primary`（`:252`）甚至"刻意避免"用它（注释说浅色下对比度掉）。全应用唯一一处渐变是导航 `:checked`（`:211-216`）用了一个 **2.4% 宽度的伪渐变技巧**（`stop:0.024`），视觉上就是纯色块。
- **问题**：配色取了 Stripe 的靛蓝，却**把 Stripe 最标志性的"柔光渐变 + 微辉光"丢了**。结果是"Stripe 的色，Material 的平"。
- **方向**：真正引入渐变语言——主 CTA 用 `accent→accent2` 渐变（用深靛保对比度，如 `#4338ca→#635bff` 而非亮青）；侧栏顶部/hero 带用极淡径向渐变；选中态用 accent 柔光（已有 `accent_tint` 可扩）。

### 🟠 A-2 · 色彩单调，全界面一个靛蓝调
- **现状**：主色 `#635bff` + 中性灰（`#f6f8fb`/`#e6e9ef` 等）贯穿全局；唯一彩色来自卡片类型小徽章（Niagara 青 / Cascade 紫 / Texture 橙…）。
- **问题**：整屏读起来是"一片靛蓝灰"，缺乏次级色与视觉节奏。讽刺点：**管理视觉特效的软件，自己却最不"视觉"**。
- **方向**：用类型色做更广的语义渗透（如侧栏分类图标、统计环），引入 1 个克制的中性暖色做强调；或给不同视图/状态一点色彩情绪。

### 🟠 A-3 · 阴影/层次薄弱，组件像"贴上去"的
- **现状**：`AssetCard` 阴影 `0 1px 2px`（`:384`）、hover `0 6px 16px`（`:386`）。只有单层、极弱投影。
- **问题**：没有"环境光 + 主光"的双层阴影语言，卡片/面板缺乏浮起感，层次扁平。
- **方向**：建立阴影 token 阶梯（如 `--shadow-sm / --shadow-md / --shadow-lg`，每层含 ambient+key），让 hover、选中、弹层有明显纵深差。

### 🟡 A-4 · 圆角无系统，半径随意
- **现状**：半径散布 6 / 7 / 8 / 9 / 10 / 14 / 20 / 24px——卡片 14（`:383`）、输入框 10（`:267`）、段控 9（`:629`）、批量条 24（`:397`）、项目 pill 20（`:652`）、下拉 8（`:340`）、对话框 8。
- **问题**：没有"半径刻度"，各处凭感觉取值，精致度打折。
- **方向**：建立 4 级半径刻度——`r-sm 6`（芯片/标签）/ `r-md 10`（输入/按钮）/ `r-lg 14`（卡片/面板）/ `r-pill 999`（药丸），全量替换。

### 🟡 A-5 · 残留硬编码，未完全 token 化
- **现状**：`#lightbox` 遮罩硬编码 `rgba(10,37,64,.55)`（`:400`）；卡片 `#cardtier`/`#cardfav` 用硬编码深色 `rgba(10,20,30,...)` 叠加（`:519`/`:524`），**不随主题切换**（深/浅都用同一层暗色，浅色下尚可，但语义上未 token 化）。
- **问题**：与"单一 token 真源"纪律不一致，主题扩展易再次踩坑（前几轮已修过一批内联，这里还漏）。
- **方向**：遮罩/叠加层也走 token（`overlay` 已定义，直接引用）。

## 三、设计感 / 品牌 / 微交互（Design Sense）

### 🟠 D-1 · 无品牌标识，产品存在感弱
- **现状**：header 的 `brand`（`:292`）只是一段文字 label，没有 logo / 字母标 / 图标符号。
- **问题**：一款工具连视觉记号都没有，记忆点为零。
- **方向**：设计一个极简 monogram（如柔光渐变的"FX"或棱镜符号）放在 header 与关于页。

### 🟠 D-2 · 空状态只有文字，无插画
- **现状**：空筛选/空库用 `cardemptylabel` 文字提示（`:552`）。
- **问题**：Stripe 级产品用友好插画化解"空"，创意工具更该如此；纯文字显得冷。
- **方向**：为"无缩略图 / 空筛选 / 空收藏"等空态配轻量 SVG 插画（风格与品牌一致）。

### 🟡 D-3 · 无微交互 / 动效，界面是"静"的
- **现状**：hover 只有阴影变化，选中/切换无过渡动画，无任何 `transition`/缓动。
- **问题**：Qt 默认无动画，界面显得"死板"，少了"活"的设计感。
- **方向**：对 hover 抬升、选中描边、视图切换、批量条滑入加 120–200ms 缓动（Qt `QPropertyAnimation` 或 CSS `transition` 等效）。

### 🟡 D-4 · 字体层级扁平
- **现状**：基础字号 13px（`:47`），标题仅 16px（`:284`/`:286`），强调靠 `font-weight` 切换；**没有真正的字号阶梯**（无 11/12/14/20/24 的 display 级）。
- **问题**：层级靠"粗不粗"区分，缺乏"大标题/小标注"的节奏感，hero 时刻没有视觉重量。
- **方向**：建立 type scale（如 caption 11 / body 13 / subtitle 14 / title 18 / display 24），在内容头/空态/统计处用大字号制造层次。

### 🟡 D-5 · 图标体系未评估一致性（提示）
- `icon()` 辅助函数统一取 SVG（从多处 `icon("plus"/"folder"/"trash"…)` 看是单色线性图标）。若全应用是**统一线性、统一描边宽度**则 OK；若存在填充/线性混用、权重不一，需收一口径。建议补充一份图标使用规范（线宽 1.5 / 圆角端点 / 24px 网格）。

## 四、 strengths（必须肯定的优点）

为避免只泼冷水，这软件在**工程级 UI 纪律**上其实做得不错，是改"美感"而不是改"地基"：

- ✅ **token 单一真源**：`style.py` 集中管理深/浅双主题，主题切换安全（此前内联 QSS 导致深浅不同步的债已清）。
- ✅ **可访问性**：焦点环 `outline` 可见（`:50-76`），星标/卡片收藏键特意去掉焦点框（`:59-61`），对比度达标。
- ✅ **语义色点**：类型徽章按 Niagara/Cascade/Texture/Material 用不同色（`:541-546`），是少有的"有设计感"的细节。
- ✅ **三视图 + 详情表交互完整**：图标/列表/详情切换、排序、拖列宽、斑马纹、右键联动均已实现。
- ✅ **卡片占位图**：渐变+字母的统一占位（N/C/B/T/M），比默认破图优雅。

> 结论：地基好，差的是"皮肤的设计语言"。下面给方向。

## 五、 redesign 方向（设计师给的"该往哪走"）

| 维度 | 现在 | 建议方向 |
|---|---|---|
| **渐变** | 几乎无（伪 2.4% 技巧） | 主 CTA 双色渐变；侧栏/hero 极淡径向渐变；选中柔光 |
| **阴影** | 单层极弱 | 双层阴影刻度（ambient+key），hover/选中/弹层有纵深 |
| **圆角** | 6~24 随意 | 4 级刻度（6/10/14/999） |
| **色彩** | 单一靛蓝灰 | 类型色做语义渗透 + 1 个克制暖色强调 |
| **布局** | 工具栏挤 / 侧栏空 | 工具栏三簇分组；侧栏死区变 hero/统计卡 |
| **品牌** | 纯文字 | 加 monogram 标识 |
| **空态** | 纯文字 | 配轻量 SVG 插画 |
| **动效** | 无 | hover/选中/切换 120–200ms 缓动 |
| **字体** | 13/16 两级 | 建 type scale（11→24） |
| **图标** | 疑似单色线性 | 立规范（线宽 1.5 / 圆角端点 / 24 网格） |

> 配套可视化：**`ui_redesign_concept.html`** —— 左为"现状（平/挤/空）"，右为"Stripe 风 redesign 概念"，可直接在浏览器打开对照。

## 六、优先级建议（只看视觉，不动功能）

| 优先级 | 项 | 成本 | 收益 |
|---|---|---|---|
| **P1（视觉杠杆最大）** | A-1 真渐变 + A-3 阴影刻度 + A-4 半径系统 | 低（全在 style.py token） | 整体"贵气感"立竿见影 |
| **P1** | L-1 工具栏三簇分组 + L-2 侧栏死区改造 | 中（布局代码） | 告别"平淡标准布局" |
| **P2** | D-1 品牌标识 + D-2 空态插画 + D-3 微交互 | 中 | 设计个性 / 记忆点 |
| **P2** | A-2 色彩节奏 + D-4 字体阶梯 + A-5 token 收口 | 低~中 | 精致度打磨 |

> 一句话：先花小成本把 **A-1/A-3/A-4**（渐变+阴影+半径）三个 token 级改动做了，界面会从"能用的默认皮"跳到"有设计语言"；再动 L-1/L-2 布局，就能摘掉"平淡"的帽子。
