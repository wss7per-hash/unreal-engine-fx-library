## 一、总体结论

**软件已从「能跑的原型」进化为「可日常使用的工具」。** 自 v0.1 打包以来，上一版评测报告列出的全部 P0（数据风险/崩溃/核心功能缺失）与 P1（明显体验缺陷）已在 07-23 ~ 07-24 的密集迭代中修复完毕。当前版本：

- **数据安全**：重扫不再抹掉用户标签/收藏/评分（upsert COALESCE 合并）；扫描单文件异常隔离不中断；SQLite 开 WAL + 自动快照备份；Unknown 资产不再被静默删除。
- **性能**：资产网格已虚拟化（仅实例化视口内卡片），万级资产可用；搜索 250ms 防抖。
- **功能闭环**：.fxpack 导出（真实递归收集依赖）→ 导入重映射闭环打通；资产健康扫描接入 UI 与检查器；资产可重命名。
- **交互稳定性**：困扰多轮的「点标签/筛选/文件夹没反应」已根治（移除 FramelessWindowHint 自定义拖拽 hack，改原生窗口 + DWM 暗色标题栏；nav 点击轻量化不再阻塞事件循环）。

**本轮迭代的重心因此转移**：不再是救火，而是 ①版本化基础设施（当前版本号只存在于 exe 文件名里，属于发布流程硬伤）②剩余 UX 打磨项。

## 三、当前问题清单（按优先级）

### P0 / P1 — 无

经逐模块核查，当前代码不存在崩溃路径、数据风险或核心功能不可用问题，也无明显功能性体验缺陷。这是三轮迭代的成果，值得肯定。

### P2 — 本轮修复项

#### P2-1｜发布工程：版本号无单一来源（本轮主项）
- **现状**：版本号只存在于 exe 文件名 `FXLibraryClient.v.0.1.exe`。代码里没有 `__version__`，窗口标题无版本，无关于对话框，exe 属性无版本资源，打包脚本不打版本戳。
- **危害**：用户报 bug 时无法确认在跑哪个版本（07-24 排查点击失效时就为「跑的是不是新版」浪费了一整轮诊断）；多个 dist 副本无法区分。
- **方案**：`app/version.py` 单一来源 → 标题栏「FX Library v0.2.0」+ 关于对话框 + Windows 版本资源 + 产物命名，全部由构建脚本统一注入。

#### P2-2｜侧栏顶部空白死区 —— 核实结果：**已修复**
- 走查发现当前 `_build_sidebar` 已无垂直 splitter：顶部为品牌/统计 hero 卡（资产总数一目了然），下方筛选 chips + 文件夹树自然流布局，文件夹树占满剩余空间。旧报告此项过期，无需改动。

#### P2-3｜工具栏无视觉分组 —— 核实结果：**已修复**
- 当前工具栏第一行已用细分隔符分为四簇：扫描（主操作）｜库操作（取缩略图/导出/体检）｜选择（全选/反选/清除）｜搜索+设置。旧报告此项过期，无需改动。

#### P2-4｜代码缺陷：`export_to_fxpack` 被定义两次
- `app/ue_export.py` 内同一函数完整复制了两份（:504 与 :620），第二份静默覆盖第一份。运行时无害，但未来任何一处单独修改都会产生隐蔽分叉。删除第二份。

#### P2-5｜死 i18n 键
- `i18n.py` 中 `f_health` / `s_health`（健康筛选/排序）从未被任何 UI 引用——排序与筛选下拉都不支持按健康状态过滤。删除死键（或后续版本把「按健康度筛选」做成真功能，roadmap 项）。

#### P2-6｜中英文案不一致
- 中文 `ctx_export_ue` =「复制到 Content 文件夹」（准确），英文 =「Export to UE Project」（暗示会导入进引擎，名实不符）。英文统一改为「Copy to Content Folder」。

### P3 — 记录在案，本轮不做（roadmap）

| P3-2 | 视觉系统缺刻度：圆角/阴影各处随手写 | style.py 建立 radius 4 级、shadow 3 级 token 刻度 |
